1 Peta Aktor & Sistem (Overview)

Empat aktor dalam rantai pasok: Levi's Principal sebagai pemasok produk, PT SES sebagai distributor (transaksi penuh di SAP), toko retail yang beroperasi dengan POS bawaan principal, dan PT EBR sebagai entitas retail yang pembukuannya dijalankan di Odoo. Odoo menerima mirroring data operasional toko.

6 Roadmap Integrasi

PHASE 1 — BERJALAN Manual Excel/CSV

  • Tim toko/operasional mengekspor report dari sistem principal dalam format Excel/CSV.
  • File diunggah/diimpor ke Odoo melalui adapter import (mapping kolom report → dokumen Odoo sudah ditetapkan).
  • Validasi manual: jumlah baris, total nilai, dan exception report sebelum posting.
  • Cocok untuk fase awal pembukaan toko dan stabilisasi master data.

PHASE 2 — BERIKUTNYA FTP/SFTP Erajaya

  • File report di-drop otomatis ke server FTP/SFTP Erajaya per jadwal (EOD/intra-day).
  • Odoo melakukan polling terjadwal: ambil file → parse → import → arsip (folder incoming/processed/error).
  • Notifikasi otomatis bila file gagal parse atau ada selisih rekonsiliasi.
  • Menghilangkan proses manual; data toko di Odoo selalu up-to-date H+0/H+1.

Fitur utama custom_retail_import (modul yang dibangun untuk onboarding Levi's, reusable untuk tenant retail lain):

Import Profile per jenis fileTiap report (X101, X20, X24, X70D, CoA, Company, Store Master) punya profil sendiri: format xlsx/csv, baris awal data, mapping kolom (JSON), parsing tanggal/desimal, perbaikan karakter rusak (U+FFFD → ®).
Upload Wizard + Dry-run PreviewUser upload file → preview hasil parsing dulu (jumlah baris, sampel mapping) sebelum commit. Mencegah salah posting.
Dedup & IdempotentSHA256 hash per file menolak file yang sama diimpor dua kali; external ID per record membuat re-import aman (update, bukan duplikat).
Audit Log + Arsip FileSetiap import tercatat: siapa, kapan, berapa baris, error apa; file sumber disimpan sebagai attachment untuk audit.
SFTP Feed Poller (Phase 2)Cron terjadwal menarik file baru dari FTP/SFTP Erajaya per jenis file (pola nama file), lalu memprosesnya lewat executor yang sama dengan upload manual.
Async untuk File BesarFile besar (X101 master produk) diproses di background via queue_job — tidak membebani sesi user dan tidak terputus timeout.
